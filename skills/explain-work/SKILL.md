# 실제 결과와 과정 이해

현재 PLAN·관련 DECISIONS·REVIEW·실제 코드/자료/결과를 대조한다. 가상의 이상적 해법이나 사용자 생각을 꾸며 쓰지 않는다. 없는 알고리즘·독립 리뷰·실행 근거를 만들어 설명하지 않는다.

## 적용 시점

중요 설계 선택 전후, 첫 결과 확인, 사용자 이해 요청, 허용된 마무리 준비에 필요한 부분만 적용한다. AI 사용이 금지되는 후속 단계에는 답변·초안 작성에 사용하지 않는다.

## 설명할 핵심

- 실제 입력→주요 처리→출력과 사용자가 보는 결과를 작은 예로 설명.
- 핵심 방법이 실제로 어떤 규칙·기간·범위를 사용하며, 왜 선택했고 다른 후보의 손익은 무엇인지.
- 요구상 고정 조건, 사용자 절충, 확인 사실, 가정의 차이와 실제 선택 위치.
- 무엇이 어려웠고 어떤 의견·실패·수정이 결과를 바꿨는지. 없었던 반론이나 기여를 만들지 않음.
- 검증 기준·기대값의 출처, 방법의 타당성·독립성, 실제 결과와 미확인 범위.
- 한계·부작용·대안·실제로 사용한 대리지표의 가정과 영향. 자세한 근거는 REVIEW로 연결.
- 실제 파일/함수·문서 ID를 짚어 사용자가 다시 찾을 수 있게 설명.

간결한 상태 보고와 이해 설명을 구별한다. 사용자가 모르겠다고 하면 같은 요약을 반복하지 말고 대표 입력·두 후보 결과 차이·처리 순서 등 구체적 예로 바꾼다.

## 필요할 때 읽을 자료로 보존

작업 중 설명은 해당 PLAN/DECISIONS/REVIEW에 연결한다. 사용자가 요청하거나 허용된 마무리에서 통합 이해 자료가 필요하면 `UNDERSTANDING.md` 또는 같은 역할의 기존 문서에 입력/처리/출력·선택 이유·검증 타당성·한계·근거 위치를 짧게 정리한다. 상세 검증 수치·실행 로그를 복제하지 않는다. 제출 필수 파일이라고 가정하지 않는다.

사용자가 자신의 말로 흐름과 이유를 설명할 수 있도록 선택적으로 확인 질문을 제시할 수 있다. 실제 후속 문항을 알고 있거나 예상 질문과 동일할 것처럼 표시하지 않는다. 사용자 답을 대신 만들거나 AI 금지 단계로 이어서 진행하지 않는다.
