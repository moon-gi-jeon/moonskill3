# 프로젝트 결과와 의사결정 해설

[문서 역할] 제출 전에 실제 결과, 선택 이유, 검증 근거와 한계를 빠르게 확인하는 해설.

[관련 기록] 요구·질문·승인은 [PLAN](PLAN.md), 선택 이력은 [DECISIONS](DECISIONS.md), 실행·검증 상세는 [REVIEW](REVIEW.md).

### [담당자 질문 → 답 → 반영 → 확인]

우선 복기 사례로 이 문답을 골랐다면 실제 조건·내 판단·AI가 바꾼 동작·내가 확인한 결과만 상단에 압축한다.

- [처음 요청·빈칸] {원문에 있던 요청과 답이 필요했던 구체적인 점.}
- [실제로 물은 질문] {본 질문 또는 꼬리 질문과 PLAN Q-ID. 기록 유형을 원문·재전달로 구분.}
- [받은 답] {실제 답의 핵심과 단서·예외. 답변에 없던 해석은 구분한다.}
- [정해진 조건과 분류] {필수·우대·고려 중 해당 항목, 분류 이유와 적용 범위. 원문과 충돌하거나 뜻이 모호하면 미확정으로 표시.}
- [내 판단과 영향] {답을 받고 내가 선택·변경·승인한 내용과 당시 남긴 이유, 바뀐 결과. AI 제안을 채택했다면 그 사실을 적는다. U/D-ID.}
- [AI가 반영한 것] {AI가 실제로 구현·수정한 기능·화면·기준과 코드 위치. 사용자가 직접 수정한 부분이 있으면 주체를 구분한다.}
- [내가 직접 확인한 것] {내가 본 화면·눌러 본 동작·직접 확인한 값과 범위. AI의 실행 검증과 구분하고 V-ID를 연결한다. 직접 확인 기록이 없으면 미확인 또는 미기록으로 표시한다.}
