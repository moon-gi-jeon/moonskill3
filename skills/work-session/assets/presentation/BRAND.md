# 표현 프로필

확인일: 2026-11-01 KST. 빨강·주황 계열을 활용하는 선택형 표현 기준이다. 공식 디자인 시스템·공식 서비스·공식 배포 템플릿이라고 표시하지 않는다. 관련 표현 작업에서 선택적으로 참조한다.

## 공식 근거

- 출처: [그룹 공통 CI 색상 규정](https://www.sk.co.kr/ko/about/ci.jsp).
- 주요 색상의 HEX: SK Red `#EA002C`, SK Orange `#F47725`.
- 보조 색상 중 사용할 수 있는 HEX: SK Navy `#0E306D`, SK Teal `#009A93`, White `#FFFFFF`, Black `#000000`.
- 로고를 별도로 사용할 경우 원문의 공간 규정을 따른다. 이 패키지는 로고를 포함하지 않으며 로고 공간 규정을 일반 카드·페이지 여백 규정으로 해석하지 않는다.
- 공식 페이지의 Orange HEX와 RGB 숫자가 일치하지 않는다. 본 프로필은 HEX 값을 선택했다. 상세 차이는 [출처 기록](SOURCES.md)에 남긴다.

## 우리 구성 원칙 — 공식 규정이 아닌 제안

### 적용 범위

사람이 보는 웹 UI, HTML 보고서, PDF·발표·차트 등 표현을 지원하는 결과물에 활용한다. 과제의 지정 템플릿·스키마·데이터 원본·사용자 접근성 요구를 우선한다. 일반 Markdown은 제목·목록·라벨로 같은 정보 계층을 구현하고 억지 색상 태그를 넣지 않는다.

### 정보와 레이아웃

1. 실제 사용자의 역할과 핵심 작업을 먼저 확인한다. 필요한 정보·대표 입력·출력·주요 이동 흐름을 설명한 뒤 합의한 첫 범위부터 만든다.
2. 페이지/문서의 상단에는 목적·현재 데이터 범위·핵심 상태·다음 행동을 둔다. 원문에 없는 실적 수치·프로젝트 이름·권한을 임의로 확정하지 않는다.
3. 흰색 계열 바탕과 진한 본문을 기본으로, Red는 주요 행동·제목 강조에 제한해 사용한다. Orange는 보조 강조에 사용한다. 오류·성공은 색만으로 구별하지 않고 텍스트 라벨을 함께 둔다.
4. 가로로 넓은 표는 필요한 열만 남기고 상세는 세로로 연다. 정렬·단위·데이터 출처·실제/예시 구별을 명확히 한다. 그래프·도식은 겹치는 라벨과 의미 없는 장식을 줄인다.
5. 웹 UI의 하위 화면은 이전 화면·관련 화면으로 돌아갈 방법을 제공한다. 운영자/일반 사용자 등 역할이 있으면 보여 줄 정보와 작업을 구분한다. 이는 과제에 실제 역할이 있을 때 적용한다.
6. 한국어 운영체제 기본 글꼴을 사용해 외부 폰트 다운로드를 기본 의존성으로 만들지 않는다. 좁은 IDE 참고 문서는 짧은 줄·제목·목록 중심으로 만든다.

### 결과물 종류별 최소 적용

- 웹: 타이포 계층·색상 토큰·역할별 정보·주요 행동·이동·빈 상태/실패 안내. 프레임워크는 지정하지 않는다.
- 보고서/발표: 간결한 제목·목차·강조 색상·표와 도표의 단위/출처·해석/한계. 색상 때문에 원자료의 의미를 바꾸지 않는다.
- 코드·API·CSV·JSON: 해당 계약과 형식 그대로 제출한다. 브랜드를 넣기 위해 출력 스키마를 바꾸지 않는다.

## 관련 작업에서 연결할 방식

work-session이 실제 표현 작업을 계획할 때 이 준비 프로필의 존재를 알고, 관련 작업에서만 frontend-design 또는 문서 지원 Skill과 연결한다. 모든 단계에서 전체 프로필을 다시 읽게 하지 않는다. 표현 방향을 준비했다는 이유로 업무 내용·화면 명칭·핵심 방법 선택까지 자동 위임된 것으로 해석하지 않는다.

로고는 공식 출처 링크를 참조한다. 재배포 허용 범위를 확인하지 않은 원본 로고 파일은 이 프로필에 포함하지 않았다. 개인 계정·원본 과제·후속 문항·개인 응시 링크도 포함하지 않는다.
