# PLAN

[문서 역할] 현재 목표·요구/출처·질문/답·합의 기준·승인 범위·작은 구현 순서와 근거 색인의 마스터.
[다른 내용의 위치] 중요한 선택 이력은 DECISIONS의 D-ID, 상세 검증은 REVIEW의 V-ID,
실제 결과의 쉬운 해설은 PROJECT_GUIDE 또는 동등 문서에서 확인한다.
실제 문서명·위치로 바꾸고 아직 없는 문서는 예정/미작성으로 구분한다.

실제 과제의 같은 역할 문서가 있으면 재사용한다. 관련 항목만 쓰며 새 정보는 해당 절에 갱신한다. 원문·협의·중요 변경 이력을 지우지 않는다.

## [현재 상태]

- 목표·필수 결과·실제 사용자는:
- 현재 단계·승인 범위·승인 근거: 해당 S-ID·상태, 관련 실제 승인 또는 승인 대기 근거
- 중요한 미결·차단·다음 행동: 관련 S/U-ID. 중요한 차단이면 멈춘 단계와 이미 승인되어 계속 가능한 일, 다음 행동 한 가지
- 실제 자료/결과/실행·미리보기 위치:
- 정본: DECISIONS / REVIEW / PROJECT_GUIDE 또는 동등 문서 / 필요한 제출 문서:
- 이번 관련 Skill: 실제 읽음/문맥 재사용/수행/미사용 사유를 필요한 때만:

## [작은 구현 순서]

첫 계획에서 최종 검증·전달까지 과제의 전체 흐름을 잡는다. 단계마다 안정적인 S-ID·상태와 사용자가 확인할 결과를 한 줄로 적는다. 첫 확인용 결과와 분리 가능한 후속 기능은 다른 S-ID를 쓴다. 뒤 단계는 예정으로 두고 새 답이나 확인 결과에 따라 갱신한다.

### [S1 · 상태] 확인할 결과 한 줄
지금 협의·승인하거나 진행할 단계에만 필요한 상세를 아래에 둔다.

- 승인 설명 위치: 관련 U/S-ID, 추가 구분이 필요할 때만 X-ID:
- 추천안·주요 근거/조건·중요 대안/손익:
- 이번 범위·대표 입력→처리→사용 가능한 출력:
- 사용자가 실제로 확인할 결과·남겨 둘 선택:
- 완료 기준·검증 ID·다음 논의 지점:
- 승인/진행 상태·실제 답·관련 계획 개정/변경 위치:

CLI에서 설명이 길면 위 항목의 상세를 이 위치에 두고,
터미널에는 추천·핵심 이유·중요 영향·승인 범위와 정확한 U/S/X-ID를 보고한다.
나머지 S 단계는 해당 ID·상태·결과의 한 줄을 이 목차에서 이어 쓴다.

## [중요한 진행·변경]

관련 절의 현재 내용을 먼저 갱신하고, 이곳에는 의미 있는 실패·복구·변경의 짧은 근거와 다음 행동만 남긴다. 폐기 항목은 [drop] + 이유·대체 위치로 구분한다. 전체 명령/대화를 복제하지 않는다. 새 D/V 상세 저장 뒤 현재 색인을 연결한다.

## [실제 전환이 필요할 때]

PLAN만으로 충분하면 별도 HANDOFF를 만들지 않는다. 필요한 인계의 위치와 유효 검증·남은 미결·다음 행동을 연결한다.
