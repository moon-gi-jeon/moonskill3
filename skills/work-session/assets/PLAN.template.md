# PLAN

실제 과제의 같은 역할 문서가 있으면 재사용한다. 관련 항목만 쓰며 새 정보는 해당 절에 갱신한다. 원문·협의·중요 변경 이력을 지우지 않는다.

## 현재 상태

- 목표·필수 결과·실제 사용자는:
- 현재 단계·승인 범위·승인 근거:
- 중요한 미결·차단·다음 행동:
- 실제 자료/결과/실행·미리보기 위치:
- 정본: DECISIONS / REVIEW / 필요한 제출 문서의 실제 경로:

## 자료·요구·제약

### R01
- 기대 동작·필수/선택:
- 출처·원문 위치·관련 답/가정:
- 입력·출력·완료 판정:
- 구현 위치·검증 ID·현재 상태:

## 담당자 질문·실제 답

### Q1 [문의필요]
- 대상·질문:
- 이유·관련 요구·우선순위:
- 상태·실제 답·출처:
- 반영·남은 가정:

## 사용자 질문·선택

### U1 [사용자결정]
- 선택할 내용·추천·근거/반례·영향:
- 실제 결정·DECISIONS 위치:

## 합의한 성공·비교·검증 기준

- 구현 순서와 별도로 성공/필수 조건·비교 목표:
- 대표/전체 입력 범위·기대값의 독립 근거:
- 중요한 가정·미확인·범위 밖:

## 후보·실험·현재 방법

- 의미 있는 후보와 차이·비용·실패 조건:
- 승인된 작은 실험·실제 비교 REVIEW 위치:
- 선택 방법·이유 DECISIONS 위치·재검토 조건:

## 작은 구현 순서

### S1
- 이번 범위·대표 입력→처리→사용 가능한 출력:
- 사용자가 실제로 확인할 결과·남겨 둘 선택:
- 완료 기준·검증 ID·다음 논의 지점:
- 승인/진행 상태·변경 위치:

## 검증 색인

- V01 / 관련 R·후보 / 짧은 실제 결과 / 상태 / REVIEW 상세 위치

## 중요한 진행·변경

관련 절의 현재 내용을 먼저 갱신하고, 이곳에는 의미 있는 실패·복구·변경의 짧은 근거와 다음 행동만 남긴다. 폐기 항목은 [drop] + 이유·대체 위치로 구분한다. 전체 명령/대화를 복제하지 않는다.

## 실제 전환이 필요할 때

PLAN만으로 충분하면 별도 HANDOFF를 만들지 않는다. 필요한 인계의 위치와 유효 검증·남은 미결·다음 행동을 연결한다.
