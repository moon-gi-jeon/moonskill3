# REVIEW

[문서 역할] 검증 사유·방법·기대값의 출처/신뢰·실제 실행/결과·한계·대안·대리지표의 상세 정본.
[다른 내용의 위치] PLAN의 검증 색인에서 해당 V-ID를 찾는다.
중요한 선택의 이유/이력은 DECISIONS, 쉬운 검증 해설과 전체 과정은 이해 문서에서 확인한다.
실제 문서명·위치로 바꾸고 아직 없는 문서는 예정/미작성으로 구분한다.

첫 관련 검증부터 실제 상세 근거를 기록한다. 비해당 사실을 만들어 채우지 않는다. PLAN은 ID·짧은 결과·상태·여기 위치만 연결한다.

## [현재 핵심 검증 안내]

### [실제 검증 주제 · 현재 상태]

- [왜] 어떤 잘못된 결과/위험을 구별하려 했는가:
- [방법] 무엇을 어떻게 따로 확인했는가:
- [기대값을 믿는 이유] 출처·독립성·공유한 가정:
- [실제 결과] 확인한 결론과 범위:
- [남은 한계] 입증하지 못한 것:
- [상세 근거] 아래에 실제 저장된 V-ID:

위 카드는 짧은 읽기층이다. 전체 로그/숫자 정본은 뒤의 V 상세에 보존한다.

## [검증 이력·실행 근거]

<a id="v01"></a>
### [V01] 실제 검증 대상

- 관련 요구·후보·D-ID·검사한 코드/입력 상태와 범위:
  후보 비교 표·목록에는 PLAN과 같은 표기(예를 들어 `C1 (전수 열거)`)를 사용한다.
- 상태:
- 성공/기대값과 출처:
- 방법·왜 타당한가·기대값 독립성:
- 실제 실행/허용 조작·관측 결과·근거 위치: 중요한 변경 분기는 발생 입력·응답·상태 변화를 확인
- [핵심 판정의 재현] 방법 선택·최종 판정을 좌우한 검사라면 실행 위치·명령·입력·기대값 산출 경로와 실제 재실행 상태
- 확인한 범위·미확인·한계·영향:
- 사용한 대안·대리지표·가정과 오해 위험(해당 시):
- 변경 시 재검증 조건·이전 근거 대체 관계:

결과와 기대를 같은 구현에서 만든 경우 이를 독립 검증으로 표시하지 않는다. 실행하지 않은 검사는 NOT_RUN, 사람이 확인해야 하는 항목은 HUMAN_CHECK, 변경으로 효력이 없어진 근거는 STALE로 구별한다.
