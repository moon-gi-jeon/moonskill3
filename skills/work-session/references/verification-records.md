# 검증 상세와 PLAN 색인

REVIEW는 첫 관련 검증부터 상세 근거의 정본으로 사용한다. 과제의 같은 역할 문서가 있으면 재사용하고 PLAN에 실제 위치를 남긴다.

## 검증 ID 아래에 필요한 내용을 기록한다

- **대상·상태:** V-ID, R-ID/후보, 실제 파일/입력 범위·버전, PASS/FAIL/NOT_RUN/HUMAN_CHECK/STALE 등.
- **기준·기대값 출처:** 무엇이 성공인지, 원문/담당자 답/사용자 합의/독립 계산 중 어디에서 왔는지.
- **방법·타당성:** 검사 절차, 어떤 오류를 잡는지, 구현과 독립적인 기대값인지. 동일 함수를 다시 호출하는 비교는 독립 검사로 세지 않는다.
- **실제 실행·결과:** 재현 명령/허용된 조작, 실제 관측, 중요한 기대/실제 차이와 근거 파일.
- **확인 범위·한계:** 무엇을 확인하지 못했는지, 영향과 적용 조건.
- **대안·대리지표:** 실제 사용했으면 이유·원래 목표와의 관계·가정·오해 위험. 검토만 한 대안과 구별한다.
- **변경 영향:** 어떤 코드·자료·규칙 변화가 이 근거를 무효화하며 무엇을 재검증할지.

해당 항목이 없는 사실을 만들어 채우지 않는다. 원시 로그 전체를 복제하지 않고 필요하면 경로로 연결한다. 문서 정리 자체는 기능 검증이 아니다.

PLAN에는 `V03 / R02 / 짧은 결과 / 현재 상태 / REVIEW.md#v03`처럼 위치를 남긴다. 근거를 현재 코드/입력과 연결하고, 변경 뒤 영향받은 이전 항목은 STALE로 보존한다. 여러 문서에 수치의 정본을 따로 만들지 않는다.

후보 세 개의 합의·리뷰어 수·다른 세션의 PASS는 독립 검산을 대체하지 않는다. 원자료 기반 기준 예, 간단한 별도 계산, 불변 조건, 변경 입력, 관련 회귀 중 실제 과제에 필요한 검사를 선택한다.
