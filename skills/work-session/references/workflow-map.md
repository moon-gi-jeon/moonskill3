# 선택형 작업 지도

필요한 단계만 적용한다. 각 행은 새 승인·문서·사용자 프롬프트를 의무화하지 않는다.

1. 자료 해석과 현재 상태 → 필수 요구·데이터 의미·Q/U 전체 목록을 PLAN에 자동 저장.
2. 답과 선택 반영 → 새 사실·요구·가정·중요 결정 갱신. 성공/비교/검증 기준을 구현 순서와 구별.
3. 핵심 방법이 열려 있으면 → 같은 필수조건의 가능해 후보(세 개 기본, 필요하면 두 개 등)를 검토. 보장 수준·총 작업 비용·전환 신호와 정량 비교를 포함한 작은 실험/검증 범위를 설명하고 승인.
4. 실험 결과 → 같은 기준으로 비교하고 추천·손익·한계를 설명. 실제 사용자 선택/위임 기록.
5. 첫 완결 흐름 → 중요한 미결 선택을 설명하고 승인 범위에서 구현. 실제 결과를 사용자에게 보여 주고 새 질문·우선순위 확인.
6. 작은 확장·검증 → 승인된 일상 작업은 계속. 중요한 의견·변경은 grill-me 검토와 실제 결정·재검증.
7. 문서·이해·마무리 → PLAN 색인·REVIEW 현재 안내/상세·DECISIONS 이유와 기본 PROJECT_GUIDE 또는 동등 문서를 대조. 상단 요약과 예상 서술형 6문항의 답변 핵심을 현재 결과에 맞추고 본문의 상세 설명을 유지.
8. 실제 전달·전환 → 저장/제출 상태 구분. 필요할 때만 HANDOFF. AI 금지 단계에는 진행하지 않음.

중요한 방법 선택이 없는 작은 작업에 세 후보나 실험을 억지로 만들지 않는다. 이미 승인한 구체적 범위를 다른 말로 다시 승인받지 않는다. 핵심 방법도 타당한 새 근거가 있으면 수정·영향 검증·필요한 재비교 대상이다.

제공 환경의 내장 위임은 지원·효용이 확인될 때만 사용한다. 메인에서 사용자 협의·구현·검증을 진행한다. 허용된 별도 Bash가 같은 저장본을 읽을 수 있으면 핵심 독립 리뷰에 쓰고, 분리 여건이 없으면 순차 확인한다. 새 실행 엔진이나 전체 앱의 병렬 구현으로 확대하지 않는다.
