# 검증 상태를 구분하는 짧은 규칙

과제에 다른 상태 표기가 있으면 그것을 재사용한다. 새 상태 관리 프로그램을 만들지 않는다.

| 상태 | 의미 |
|---|---|
| PASS | 실제 수행한 관련 검사에서 기대와 실제가 일치. 대상 파일/입력과 근거를 연결 |
| FAIL | 실행 오류 또는 기대와 불일치. 영향 요구와 다음 행동 기록 |
| NOT_RUN | 검사·호출을 수행하지 않음. 통과로 해석하지 않음 |
| HUMAN_CHECK | 사람의 화면·조작·접수 확인이 필요. 실제 확인 전에는 PASS 아님 |
| NOT_APPLICABLE | 해당 과제에 없는 기술·단계. 미검증을 성공으로 바꾸는 표기가 아님 |
| STALE | 입력·규칙·관련 파일이 바뀌어 이전 검사를 현재 근거로 사용할 수 없음 |

테스트 0건·전부 skip·결과에 맞춘 기대값 변조·HTTP 200 안의 오류 본문을 PASS로 보고하지 않는다. 실제 결과·검사 종류·사람 관찰을 구분하고 관련 근거만 보존한다.
