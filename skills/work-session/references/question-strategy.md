# 담당자 질문과 사용자 질문

원문·참조 자료·실제 답을 먼저 읽고, 답에 따라 결과·범위·기준·중요 선택이 바뀌는 빈칸을 찾는다. 고정 분야의 질문표를 대입하지 않는다.

## 목록을 한 번에 정리

PLAN에 담당자 **Q1…Qn [문의필요]**와 사용자 **U1…Un [사용자결정]**를 구분해 한 번에 목록화한다. 각 질문의 출처·영향 요구·우선순위·앞선 답 의존 여부를 필요한 만큼 짧게 둔다. 질문 하나씩만 모델이 제시하도록 제한하지 않는다.

사용자는 필요한 질문을 선택해 담당자에게 전달하고 실제 답을 모델에 알려 준다. 담당자가 질문별 전달을 요구하면 사용자가 개별로 보낸다. 하네스가 대신 전송하거나 보냈다고 기록하지 않는다. 사용자가 위임받은 판단을 담당자에게 재확인할지도 제한하지 않는다.

## 질문의 대상과 내용

- 업무 담당자: 실제 목표·업무 흐름·입력/출력 의미·규칙·예외·성공 조건의 빈칸.
- 사용자: 근거가 있는 대안의 선택·절충·범위·중요 표현 방향.
- 운영 지원: 환경·허용 도구·접속·제출 장애. 업무 정책 질문과 구별.
- 모델이 파일·실행으로 확인할 기술 사실은 직접 확인한다.

사용자에게 실제 선택을 요청할 때는 선택지·추천/근거·중요 반례·영향·받은 답/선택·상태를 같은 U 항목에 둔다. 근거가 부족하면 추천 보류 또는 조건부 추천을 명시한다. 실제 답을 받으면 같은 항목과 관련 PLAN/DECISIONS를 자동 갱신한다. 사용자 관찰만 필요한 항목에는 추천 확인 방법을 제시하고 관찰을 꾸미지 않는다.

질문은 원문이나 대표 사례와 연결해 구체적으로 작성한다. 독립 질문마다 구분된 ID를 쓰고, 이유·영향은 PLAN에 둔다. 포괄적인 '전부 알려달라'나 요구를 유도하는 질문을 피한다.

## 답과 새로운 질문

실제 답의 중요 의미·출처·부분 답변/확인 불가를 저장하고 영향받는 요구·가정·계획·기대값을 갱신한다. 중요한 선택은 DECISIONS, 노후화한 검증은 REVIEW에 연결한다. 사용자에게 달라진 내용과 다음 판단을 설명한다.

첫 결과·새 자료·검증 실패·사용자 개선 의견 뒤 **새로운 중요한 빈칸이 드러났는지 다시 검토**한다. 새 질문을 목록에 추가하되 이미 충분한 답을 기계적으로 반복하지 않는다. 실제 답과 추론·가정을 섞거나 없는 승인·답변을 만들어 기록하지 않는다.
