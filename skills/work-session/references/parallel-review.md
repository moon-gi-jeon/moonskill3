# 조건부 내장 작업자·독립 리뷰

메인 터미널이 구현과 공식 기록을 맡는다. 이미 별도로 실행된 다른 Codex 터미널을 제어하는 기능과 메인 세션의 내장 작업자 생성·회수는 다르다. 다른 환경의 제품 기능·역할 파일만으로 이 환경에서 실행된다고 가정하지 않는다.

제공 도구·안내에서 실제 내장 지원과 허용 범위를 확인하고 유용한 좁은 작업에만 사용한다. 미지원·거절·실패이면 대안을 기록하고 직접 검사/순차 수행한다. 같은 실패를 반복하거나 새 실행 엔진·MCP·플러그인·인증·관리 설정 변경으로 기능을 만들지 않는다.

## 역할 분리

메인이 최종 판정과 REVIEW를 맡는다. 허용된 내장 작업자는 요구 누락 후보, 파일 탐색, 경계 입력 제안 등 좁은 보조 작업에 쓴다. 원자료만으로 기대값을 먼저 고정할 수 있는 경우에만 독립 검산을 맡긴다. 메인의 기대값을 이미 공유했다면 보조 검토로 기록한다.

별도 Bash 사용과 같은 저장본 접근이 허용되고, 핵심 결과의 독립 검토 가치와 재현·수정 시간이 확보되면 사용자가 두 번째 세션을 선택할 수 있다. 선정한 핵심 알고리즘이나 결과를 좌우하는 필수조건의 첫 검증 뒤가 적절하다. 같은 검토는 한 경로에 맡긴다.

- 메인은 핵심 방법이나 결과를 좌우하는 제약의 첫 저장·검증을 보고할 때 검토 가치, 허용 여부와 남은 시간을 판단한다. 별도 검토의 실익이 확인되면 `[핵심 기능으로 독립 리뷰 추천]`과 바로 붙여 넣을 완성 요청 한 블록을 같은 응답에 출력한다. 실제 두 번째 세션은 사용자가 선택해 시작하며, 추천은 진행을 막는 승인 조건이 아니다. 실제 원문·확정 조건의 위치, R-ID, 대상 함수/파일과 저장 상태, 정확한 입력 파일·사례 ID, 검토 질문, 결과 파일을 채운다. 기존 D/V는 검산 후 대조용으로 명시한다.
- 리뷰 세션은 원문·확정 조건·원본 입력으로 기대값을 먼저 기록한 뒤 저장 결과와 기존 근거를 대조한다. 코드·입력·정본은 읽기 전용이며, 결과는 실제로 리뷰를 맡겼을 때 생성하는 `INDEPENDENT_REVIEW.md`에만 쓴다. 리뷰 대상 버전, 발견 번호·위치·재현 방법·기대/관측·영향·미확인 범위를 기록한다. 후속 작업을 무효화할 수 있는 발견에는 즉시 전달 표시를 한다.
- 메인은 겹치지 않는 작업을 진행한다. 사용자는 치명적 발견을 즉시, 그 외에는 다음 작은 작업 뒤 선택해서 전달한다. 메인은 현재 저장본에서 다시 재현하고 승인 범위 안에서 수정·재검증한 후 REVIEW에 반영 여부와 근거를 연결한다. 핵심 방법·판정 기준·승인 범위 변경은 사용자 판단을 받는다. 발견이 없었다면 검토한 범위와 결과를 기록한다.

## 적합한 범위

- 자료별 읽기 전용 요구/누락 대조.
- 특정 핵심 로직·중요 기대값·검증 빈칸 검토.
- 공통 기준이 합의되고 독립 파일로 나뉘며 시간 이득이 예상될 때 후보 핵심 실험 분담.

전체 앱을 여러 작업자가 동시에 만드는 방식·상시 역할 팀은 사용하지 않는다. 메인이 PLAN·DECISIONS·REVIEW의 정본과 사용자 논의·통합을 책임진다. 기본 검토자는 읽기 전용이며 검사가 상태를 바꾸면 허용된 별도 임시 영역을 사용한다.

## 위임에 포함할 것

목표 / 원문과 R-ID / 입력·대상 파일 / 권한·파일 소유권 / 실제 지원 도구 / 완료 조건 / 기대 출력. 필요한 원자료만 주고 결론을 미리 주입하지 않는다. 독립성이 필요하면 서로의 판단을 보기 전에 초기 검토하게 한다.

결과는 발견·원문/위치·영향·재현/관측·미검증·다음 확인으로 반환한다. 의미 없는 PASS나 억지 지적을 요구하지 않는다.

메인은 중복·오탐·충돌을 확인하고 실제 수정·관련 재검증 후 REVIEW에 근거, PLAN에 요약/상태/위치를 남긴다. 리뷰어 PASS와 실제 실행·독립 기대값은 구별한다. 같은 세션의 역할 전환은 독립 리뷰라고 기록하지 않는다.

시간 이득에는 맥락 전달·설정·대기·회수·통합·오탐 검토·재검증과 토큰 소비를 포함한다. 측정하지 않은 절약률을 단정하지 않고 필수 완성과 사용자 이해를 지연시키지 않는다.
