# 조건부 내장 작업자·독립 리뷰

사용자는 메인 터미널 한 곳을 쓴다. 이미 별도로 실행된 다른 Codex 터미널을 제어하는 기능과 메인 세션의 내장 작업자 생성·회수는 다르다. 다른 환경의 제품 기능·역할 파일만으로 이 환경에서 실행된다고 가정하지 않는다.

제공 도구·안내에서 실제 내장 지원과 허용 범위를 확인하고 유용한 좁은 작업에만 사용한다. 미지원·거절·실패이면 대안을 기록하고 직접 검사/순차 수행한다. 같은 실패를 반복하거나 새 실행 엔진·MCP·플러그인·인증·관리 설정 변경으로 기능을 만들지 않는다.

## 적합한 범위

- 자료별 읽기 전용 요구/누락 대조.
- 특정 핵심 로직·중요 기대값·검증 빈칸 검토.
- 공통 기준이 합의되고 독립 파일로 나뉘며 시간 이득이 예상될 때 후보 핵심 실험 분담.

전체 앱을 여러 작업자가 동시에 만드는 방식·상시 역할 팀은 사용하지 않는다. 메인이 PLAN·DECISIONS·REVIEW의 정본과 사용자 논의·통합을 책임진다. 기본 검토자는 읽기 전용이며 검사가 상태를 바꾸면 허용된 별도 임시 영역을 사용한다.

## 위임에 포함할 것

목표 / 원문과 R-ID / 입력·대상 파일 / 권한·파일 소유권 / 실제 지원 도구 / 완료 조건 / 기대 출력. 필요한 원자료만 주고 결론을 미리 주입하지 않는다. 독립성이 필요하면 서로의 판단을 보기 전에 초기 검토하게 한다.

결과는 발견·원문/위치·영향·재현/관측·미검증·다음 확인으로 반환한다. 의미 없는 PASS나 억지 지적을 요구하지 않는다.

메인은 중복·오탐·충돌을 확인하고 실제 수정·관련 재검증 후 REVIEW에 근거, PLAN에 요약/상태/위치를 남긴다. 리뷰어 PASS와 실제 실행·독립 기대값은 구별한다. 같은 세션의 역할 전환은 독립 리뷰라고 기록하지 않는다.

시간 이득에는 맥락 전달·설정·대기·회수·통합·오탐 검토·재검증과 토큰 소비를 포함한다. 측정하지 않은 절약률을 단정하지 않고 필수 완성과 사용자 이해를 지연시키지 않는다.
