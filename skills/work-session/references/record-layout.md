# 찾기 쉬운 정본과 사용자 결정

같은 역할의 기존 과제 문서를 우선한다. 아래는 탐색 형식이며 모든 내용을 매 단계 새로 복제하는 서식이 아니다.

## [문서 상단 — 역할과 확인 경로]

직접 작성·관리하는 과제 문서에는 제목 다음에 `[문서 역할]`과 `[다른 내용의 위치]`를 짧게 둔다. 실제 파일명·ID를 쓰고 동등 문서를 재사용한다. 아직 없는 문서는 예정/미작성이라고 표시하며 빈 파일을 먼저 만들지 않는다. 지정 제출 양식이 고정되어 있으면 허용된 소개 위치나 PLAN의 문서 안내에서 역할을 설명한다. 제공 원문·데이터·라이선스에 이 규칙을 적용해 덮어쓰지 않는다.

- PLAN: 현재 목표·요구/출처·질문/답·합의 기준·승인 범위·작은 순서·근거 색인의 마스터. 실제 검증의 상세 정본은 REVIEW, 중요한 선택 이력은 DECISIONS다.
- DECISIONS: 실제 중요한 선택·선택자·이유·버린 대안·한계·대체 관계. 현재 계획은 PLAN, 실행 검증은 REVIEW다.
- REVIEW: 검증 사유/방법·기대값 출처/신뢰·입력/버전·실제 결과·한계·대안·대리지표의 상세 정본. PLAN의 V-ID 색인에서 찾아온다. 쉬운 전체 해설은 이해 문서다.
- PROJECT_GUIDE 또는 동등 문서: 실제 과제의 목적·방법·선정 근거·수행 과정·주요 검증·한계·사용자 개입의 상세 해설과 상단 항목별 요약. 판단/검증 원문은 DECISIONS/REVIEW로 연결한다.
- 과제 지정 사용법/협업 문서: 실제 사용 절차 또는 실제 협업 문항의 사실/근거라는 목적을 밝힌다. 내부 진행 원장을 추가하지 않는다.
- 필요한 경우의 HANDOFF: 재개용 요약과 정본/다음 행동 연결. 새 정본이나 매 단계 필수 문서가 아니다.

역할은 실제 내용과 맞아야 한다. 소개를 넣었다는 이유로 실행되지 않은 검증이나 사용자 이해가 확인됐다고 하지 않는다. 상단에 긴 문서 목록을 복제하지 않고 관련 역할/실제 위치만 둔다.

## [PLAN — 현재 마스터]

- [현재 상태]: 기존 여섯 항목을 쓰고 현재 단계·다음 행동에 해당 S-ID를 연결한다. 중요한 차단이면 관련 U-ID와 멈춘 단계, 이미 승인되어 독립적으로 진행 가능한 일, 다음 행동 하나를 구분한다.
- [작은 구현 순서]: 현재 상태 바로 아래에 둔다. 첫 PLAN에서 최종 확인·전달까지 각 단계의 S-ID·상태·확인할 결과를 한 줄씩 보여 준다. 예정 단계는 질문 답이나 결과에 따라 갱신하며, 협의·승인하는 단계의 상세는 해당 S 또는 U에만 둔다. 같은 단계의 ID를 유지하고 진행 상태를 바꾼다. 기존 자유 양식 PLAN을 실제로 갱신할 때도 해당 목차가 아래에 있으면 이 위치로 옮긴다.
- [자료·검토 범위]: 자료 역할, 읽은 범위와 미확인. 결과를 바꿀 때만 행의 의미·고유키·기간·단위·분모·결측/중복 처리 중 해당 기준을 기록하고 성공 기준과 검증에 연결한다.
- [필수조건]: 양보할 수 없는 판정과 관련 R-ID의 짧은 색인.
- [제약조건]: 실행·데이터·도구·업무 제약과 관련 R-ID.
- [요구기능·제출물]: 기능/문서/형식의 관련 R-ID.
- [요구 상세]: 각 요구의 실제 출처·기대 동작·완료 기준·실제 반영/검증 위치. 상세의 정본은 여기에 한 번만 둔다.
- [담당자 Q 전체 목록], [사용자 U 전체 목록]: 답과 상태를 같은 항목에서 갱신한다.
- [성공·비교·검증 기준], [후보·선택한 방법], [검증 색인], [중요 변경·인계].
- 지정 제출물은 최종 확인과 재개 시 해당 R-ID에서 경로/형식, 현재 저장 여부, 내용·형식의 검증 근거, 실제 제출 확인을 구분한다. 사용자 또는 플랫폼 근거가 있어야 제출 확인으로 기록한다. 과거 작성 기록은 현재 파일 확인을 대신하지 않는다.

시스템과 사람의 판단 범위가 결과에 영향을 주면 기존 요구의 R-ID 아래에 [처리 책임]을 한 줄로 둔다. 이미 확정한 규칙과 관련 Q-ID를 연결한다.

과제 지정 양식이 허용하면 실제 PLAN에서 [필수조건], [제약조건], [요구기능·제출물]을 각각 독립 목차로 유지한다. 각 색인은 짧은 설명과 R-ID를 담고 상세는 요구 정본에 한 번만 둔다. 분류는 겹칠 수 있다. 예를 들어 역할별 조회 기능은 필수 기능과 접근 범위 제약을 함께 가질 수 있다. 분류 수를 맞추려 조건을 바꾸거나 같은 요구의 상세를 여러 번 관리하지 않는다.

## [사용자 U 항목]

한 항목에서 아래를 찾을 수 있게 한다.

- [질문/선택]: 지금 사용자가 무엇을 결정해야 하는가.
- [선택지]: 실제 가능한 대안과 중요한 손익.
- [추천]: 어떤 안을 왜 추천하는가. 중요한 반례·적용 조건도 제시한다.
- [영향]: 선택하면 바뀌는 결과·범위·위험·추가 작업.
- [받은 답/선택]: 실제 답, 선택 또는 구체적 위임. 없으면 없음.
- [상태/다음]: 답변 대기 / 선택됨 / 위임됨 / 보류 / 대체됨과 D-ID·다음 행동.

순수한 관찰 요청에는 선택지를 꾸미지 않는다. 필요한 관찰과 추천 확인 방법을 적고 사람 확인 전 성공으로 처리하지 않는다. 지난 이력에 없었던 추천·반론·답을 소급 생성하지 않는다.

## [승인 설명과 CLI 연결]

중요한 승인 지점의 설명에는 실제 추천안·이유/조건·영향, 이번 포함/제외와 사용자에게 보일 결과, 다음 확인 지점을 둔다. UI라면 실제 역할/요구에 맞는 첫 화면의 주요 정보·보조 정보와 적용할 표현 프로필을 구체적으로 추천한다. A/B/C 같은 양식 문구를 실제 계획 대신 보고하지 않는다. 추천 근거가 부족하면 조건부 또는 추천 보류 이유를 명시한다.

설명은 해당 U나 작은 구현 단계 아래에 둔다. 기존 U/S-ID로 충분하면 재사용하고, 구분이 더 필요할 때만 `[X01 · 실제 설명 제목 · 제안/승인 대기/승인됨/대체됨]`처럼 안정적인 설명 ID를 쓴다. 개정/현재 적용 상태와 실제 승인 답을 연결하고 지난 의미 있는 결정은 보존한다. 별도 설명 원장·파일·새 승인 단계는 만들지 않는다.

터미널에는 지금 결정할 것·추천·핵심 이유·중요 조건/위험·승인 범위를 짧게 남기고 `PLAN.md → [실제 U/S/X-ID · 제목]`으로 상세 위치를 표시한다. 필요한 설명을 문서 링크 하나로 모두 대신하지 않는다. 동의가 없는데 문서의 상태만 승인됨으로 바꾸지 않는다. 이미 구체적으로 승인된 일상 구현/버그 수정은 기존 원칙대로 계속한다.

좁은 IDE용 설명은 짧은 문단/목록으로 쓰고 길게 이어진 설명 행은 문장·의미 단위로 줄바꿈한다. 명령·URL·식별자·고정 제출 스키마를 자르거나, 줄을 줄이기 위해 수치/근거/한계를 없애지 않는다. 매번 전체 PLAN을 다시 정리하지 않는다.

## [REVIEW — 읽기층과 상세 이력]

앞에는 현재 핵심 검증을 업무 의미로 묶는다. 각 카드의 [왜] [방법] [기대값을 믿는 이유] [실제 결과] [남은 한계] [상세 V-ID]를 짧게 설명한다. 처음 보는 사람이 ‘무엇을 왜 확인했고 어디까지 믿을 수 있는가’를 이해할 수 있어야 한다.

뒤에는 기존 V-ID별 실행 방법·출력·버전·한계·변경 영향·대체 관계를 보존한다. 앞의 카드에는 핵심 결론과 링크만 두고 전체 로그/숫자 정본을 다시 복제하지 않는다. 과거 PASS가 현재도 유효한지 카드와 상세 상태를 함께 갱신한다.

## [DECISIONS와 이해 문서]

DECISIONS는 중요한 실제 선택·이유·버린 대안·영향·대체 관계다. 사용자 직접 판단, 사용자 지시/승인에 따른 AI 구현, 위임 범위의 AI 기술 판단, 사용자 직접 수정을 구별한다. 이유가 기록되지 않았으면 확인 필요로 두며 기여를 꾸미지 않는다.

PROJECT_GUIDE 또는 동등 문서는 실제 결과를 이해하는 읽을 자료다. 정본을 해설하며 상세 검증 로그나 또 다른 진행 원장을 만들지 않는다. 자세한 설명과 상단 항목별 요약은 목적이 다르므로 모두 제공한다.

## [갱신과 저장 순서]

실제 새 사실→영향받는 요구/질문/계획, 중요한 결정→DECISIONS, 실제 검사→REVIEW 상세를 먼저 저장한다. 이어 PLAN의 현재 상태/색인과 이해 문서의 관련 설명을 갱신한다. 매 명령마다 모든 파일을 다시 쓰지 않는다.

중단 뒤에는 새로 참조한 항목이 실제 존재하는지 확인한다. 비어 있는 예정 ID를 과거 완료 사실로 복원하지 않는다. 한국어·정확한 명령/단위·현재와 과거·링크를 함께 확인한다.
