# moonskill3 — Work Session

자료를 이해하고 계획을 승인한 뒤, 작은 결과를 함께 확인하며 판단과 검증 근거를 자동 보존하는 가벼운 Codex 지침 패키지입니다.

## 들어 있는 것

- 진입점 `work-session`과 보조 Skills: **총 10개 폴더**.
- PLAN·DECISIONS 자동 기록, 기본 REVIEW 상세 검증과 PLAN 색인.
- 중요한 선택의 grill-me 검토, 필요한 핵심 후보 비교, 첫 결과의 사용자 확인.
- 기존 문서 Skill을 조정한 문서 정리와 실제 결과·과정 이해 지원.
- 별도 [표현 프로필](skills/work-session/assets/presentation/BRAND.md)·[색상 토큰](skills/work-session/assets/presentation/tokens.json)·[출처](skills/work-session/assets/presentation/SOURCES.md).
- 사용자 전용 [짧은 순서형 프롬프트 참고서](PROMPTS.md), 기존 규칙을 보존하는 [AGENTS 안내](AGENTS.md).
- 실제 전환 때만 쓰는 HANDOFF 양식과 조건부 내장 리뷰 지침.

실행 엔진·훅·MCP·외부 모델 키·전역 설정 변경이 필요하지 않습니다. Skill은 모델이 읽는 작업 지침이며 도구 권한이나 강제 실행 기능을 추가하지 않습니다. 모든 Skill을 설치하되 필요한 상황의 지침만 읽습니다.

## 설치 — 가장 짧은 요청

```text
공개 HTTPS github.com/moon-gi-jeon/moonskill3의
README와 manifest를 읽고 현재 프로젝트에 전체 설치해줘.
해시·목록 인식·호출 여부를 구분해 보고해줘.
```

### 설치하는 모델이 따를 절차

1. 실제 과제 루트·기존 지침·허용 경로를 확인합니다. 공개 HTTPS clone 또는 다운로드로 이 저장소를 취득합니다. 예: `git clone https://github.com/moon-gi-jeon/moonskill3.git`. 임의로 기존 프로젝트 경로를 덮어쓰지 않습니다.
2. `manifest.json`의 파일과 프로필을 읽습니다. 기본 `all`은 아래 10개 Skill 전부입니다. 가져온 원본 참고 폴더의 manifest·출처·라이선스·고지를 보존합니다.
3. 현재 세션의 실제 Skill 발견 경로를 확인합니다. 표준 프로젝트 경로는 `.agents/skills`입니다. `skills/`의 각 폴더를 그 아래 복사합니다. Skill 안의 references·assets·라이선스도 함께 보존합니다. 다른 출처·사용자 수정 여부가 불명확한 동명 파일은 교체하지 않고 알립니다. 해시가 같은 파일은 유지하고, 이 패키지의 수정되지 않은 구버전으로 확인되며 갱신 요청이 있으면 해당 파일만 갱신합니다.
4. **manifest의 SHA-256과 설치된 각 파일을 대조**합니다. 취득한 원본 파일·설치 파일·문서 배치 경로를 구분합니다. 프로젝트 README·설정·Git 상태를 자동 변경하지 않습니다.
5. `PROMPTS.md`를 Skill 밖의 `docs/moonskill3/PROMPTS.md` 또는 과제가 허용하는 동등한 참고 위치에 둡니다. 기존 파일이 다르면 보존하고 실제 위치를 알립니다. 가이드의 자동 읽기·양식 출력은 등록하지 않습니다.
6. 아래 AGENTS 절차로 기존 규칙을 보존하는 포인터를 적용합니다. 현재 세션에서는 적용한 포인터와 설치된 work-session을 명시적으로 읽습니다.
7. **파일 설치·해시 / 목록 발견 / 실제 호출·지침 적용**을 나누어 확인합니다. 복사만으로 이미 열린 세션의 재로딩을 가정하지 않습니다. 목록이 안 갱신되면 해당 환경의 안내대로 새 세션/발견 갱신을 확인합니다. 버전 업데이트·권한 우회로 해결하지 않습니다. 직접 파일을 읽는 대안은 가능하나 이를 `$` 호출 성공이라고 보고하지 않습니다.

외부 설치 프로그램이나 전역 도구를 실행할 필요가 없습니다. 설치 원본·참고서가 공식 제출물에 포함돼야 하는지는 실제 과제 조건을 따릅니다. `workflow-only` 부분 설치도 가능하지만 관련 보조 Skill 부재를 숨기지 않습니다.

### AGENTS 보존과 한 하네스 원칙

기존 `AGENTS.md`를 먼저 읽습니다. 없고 추가가 허용되면 이 패키지의 안내를 배치할 수 있습니다. 기존 파일을 덮어쓰거나 전체를 붙이지 않습니다. 연결이 없을 때만 충돌 없는 짧은 식별 블록을 추가합니다.

```markdown
<!-- work-session:begin -->
허용된 작업에 .agents/skills/work-session/SKILL.md를 적용한다.
PLAN·DECISIONS·REVIEW와 실제 파일을 대조하고 관련 변경을 자동 기록한다.
사용자 프롬프트 참고서는 자동 읽거나 양식을 출력하지 않는다.
기존 과제 지침·사용자 승인 범위가 우선이다.
<!-- work-session:end -->
```

실제 다른 경로면 포인터를 바꿉니다. 같은 블록을 중복 추가하지 않습니다. 파일 변경이 금지되거나 충돌하면 기존 규칙을 유지하고 `$work-session` 직접 호출로 진행합니다. 다른 킷의 전체 하네스·원장·승인 규칙까지 함께 지휘하게 하지 않습니다. 유용한 독립 기능만 적용 범위와 충돌을 확인해 참조합니다.

## 시작과 이후 흐름

```text
$work-session 과제와 자료를 읽고 Q/U와 PLAN을 정리해줘.
중요한 기준은 grill-me로 검토하고
이번 작은 실험/첫 결과를 설명한 뒤 내 승인을 기다려.
```

자료 해설·Q/U 전체 목록 → 실제 답 반영 → 성공/비교/검증 기준 합의 → 필요한 핵심 후보 실험 승인 → 비교·선택 → 첫 완결 결과·사용자 확인 → 작은 확장·검증 → 문서·이해·전달 순서로 진행합니다. 작은 과제에 모든 단계를 강제하지 않습니다.

- **사용자:** 실제 답·관찰·선택·승인을 전달하고 첫 결과와 제출 상태를 확인합니다.
- **모델:** 구체적인 범위·결과·대안을 설명하고 관련 기록을 자동 갱신합니다. 이미 승인한 일상 작업마다 다시 허락을 묻지 않습니다.
- 담당자 Q와 사용자 U는 PLAN에 **한 번에 목록화**합니다. 필요한 질문을 개별 전달하는 동작과 구별합니다. 담당자 재확인 여부는 사용자가 판단합니다.
- 중요한 선택은 이유·반례·대안·영향을 검토한 뒤 실제 결정과 실행·검증으로 연결합니다. 간결한 반례만 제시하고 멈추지 않습니다.
- 방법 선택이 결과를 바꾸면 의미 있는 **세 후보의 핵심 실험을 기본**으로 합니다. 후보별 완성 앱은 만들지 않습니다. 지정된 방법이나 의미 없는 대안은 사용자와 조정합니다. 선택한 방법도 타당한 새 근거가 있으면 변경·재검증할 수 있습니다.
- 첫 구현 승인은 실제 이번 범위·사용자가 볼 결과·남겨 둘 선택·다음 논의 지점을 설명한 뒤 받습니다. 전체를 알아서 완성하라는 넓은 승인으로 해석하지 않습니다.
- 보고는 **한 것 / 근거 / 사용자가 정할 것 / 다음 할 것**입니다. 필요한 설명은 작은 예와 문서 위치로 충분히 제공합니다.
- 없는 선택 기능을 반복 탐색하거나 새 실행 엔진을 만들지 않습니다. 필수 차단은 미완료로 남깁니다.
- 내장 작업자는 실제 지원·허용·시간 효용이 있을 때만 좁게 사용합니다. 사용자는 메인 터미널 하나를 쓰고, 전체 앱 병렬 구현·수동 터미널 전달을 기본으로 요구하지 않습니다.

## 문서와 표현 프로필

- **PLAN:** 현재 목표·요구·출처·Q/U/실제 답·기준·승인 범위·작은 단계·검증 색인.
- **DECISIONS:** 중요한 실제 선택·이유·버린 대안·한계·대체 관계.
- **REVIEW:** 방법·기대값 출처·타당성·실제 실행/결과·한계·대안·대리지표·변경 영향. PLAN에는 ID·짧은 결과·상태·상세 위치.
- **과제 지정 문서:** 실제 독자와 제출 형식에 맞춰 작성합니다. 사용법에 내부 토론을 섞지 않습니다.
- **HANDOFF:** 실제 전환에 유용할 때만 정본을 연결하는 짧은 요약.
- **UNDERSTANDING:** 통합 설명이 필요할 때 실제 결과·방법·선택 이유·검증·한계의 읽기 자료. 필수 제출 파일이나 금지된 후속 단계 답안으로 취급하지 않습니다.

새 정보는 해당 목차에 갱신하고 `[drop]`·대체 이유를 보존합니다. 원문과 자세한 실행 근거를 여러 파일에 복제하지 않습니다. 별도 WORKLOG·상태 엔진은 없습니다.

표현 프로필은 **별도 문서와 데이터 파일**입니다. 웹 UI뿐 아니라 표현을 지원하는 사람용 보고서·차트 등에 적용할 수 있으며, frontend-design/문서 작업에서 관련 부분만 읽습니다. 필수 형식·역할별 정보·가독성이 우선이고 CSV/JSON 스키마를 바꾸지 않습니다. 공식 규정과 자체 배치 제안은 출처 문서에서 구별하며 로고 바이너리는 포함하지 않습니다.

## 포함 Skill과 적용 시점

| 이름 | 역할 |
|---|---|
| work-session | 전체 협업 흐름·자동 기록 |
| grill-me | 중요한 결정 검토 진입점 |
| grilling | grill-me가 연결하는 실제 질문·검토. 중복 인터뷰 안 함 |
| verification-before-completion | 완료 주장 전 실제 근거 |
| frontend-design | 실제 UI·표현 설계 |
| diagnosing-bugs | 관찰된 중요한 오류 진단 |
| api-tester | 실제 API의 허용된 HTTP 검사 |
| api-and-interface-design | 실제 API/인터페이스 계약 |
| documentation-and-adrs | 기존 문서 관례·사실·결정 이유 보존과 가독성 |
| explain-work | 실제 결과와 과정·검증·한계 이해 |

Skills의 설치·발견은 과제 완성·실제 호출·동작 준수의 증명이 아닙니다. 실행하지 않은 것과 사람 확인을 구별합니다. AI 사용이 금지되는 단계에는 진행하지 않습니다.
